הבדיקות משתמשות בהודעות על ספרייה, גן ציבורי ולוח תחבורה בלבד. כל קובצי העבודה וה־Git הזמני נמצאים ב־TemporaryDirectory; אין רשומות ייצור, קריאת פרומפטים, פרסום נתונים או בקשות רשת. imports קוראים הגדרות יישום קיימות, שאינן נתוני בדיקה. יצירת טקסט וקטלוגים מוחלפים ב־mocks כאשר נבדקת שמירת פלט CLI; לא נבחנת יצירת תוכן.

## כיסוי

- קריאה/כתיבה חוזרת של JSON ו־JSONL, תווי Unicode ושורות חדשות; קלט קטוע, UTF-8 פגום, שורה פגומה, קובץ חסר ויעד שהוא תיקייה.
- כשל כתיבה חלקית המדמה דיסק מלא, כשל החלפה המדמה sharing violation, וכשל פרסום כאשר hard links אינם זמינים. נבדק שימור היעד וניקוי קבצים זמניים בכשל שניתן לתפוס.
- מניעת דריסה של פלט קיים, כשל serialization ואפשרות ניסיון חוזר, ומרוץ אמיתי בין תהליך שכותב קובץ לבין פרסום פלט ללא דריסה.
- הריגה מבוקרת של תהליכים לפני/אחרי replace ולפני/אחרי קישור בלעדי; נבדק שאין פלט ריק או JSON חלקי ושאפשר לחזור לכתיבה תקינה.
- נעילה מתחרה בין תהליכים, שחרור אחרי חריגה והתאוששות אחרי הריגת המחזיק. קובץ הנעילה נמצא בתיקיית הבדיקה בלבד.
- כשל בקובץ השני מתוך שניים ושחזור באמצעות ניסיון חוזר, ללא הנחה שקיימת עסקה גלובלית.
- CLI עם JSON פגום מחזיר שגיאה ללא traceback ובלי יצירת פלט; פקודות Git פועלות בריפו זמני בלבד. כשלי HTTP ו־JSON תגובה נבדקים באמצעות mocks, ללא שרת אמיתי.

בתהליכי הבדיקה מותקן audit hook החוסם חיבורי רשת, פתיחת תיקיות תוכן הייצור וכתיבה מחוץ לתיקיית הבדיקה. טיימאאוטים וניקוי תהליכים מונעים הישארות תהליכי בדיקה רצים.

## ליקויים שתוקנו

1. `write_file` התחיל את אזור ה־finally רק אחרי הכתיבה, ולכן כשל בזמן כתיבה השאיר קובץ זמני. אזור הניקוי מכסה כעת גם כתיבה וסגירה שנכשלו. קובץ היעד נשאר ללא שינוי בכשל לפני הפרסום.
2. פלט CLI נפתח ב־`xb` לפני serialization/כתיבה; כשל השאיר יעד ריק או חלקי וחסם ניסיון חוזר. כעת הבתים מוכנים ונכתבים לקובץ זמני לפני פרסום בלעדי באמצעות hard link באותה תיקייה. אם היעד קיים או נוצר במקביל, מתקבלת FileExistsError והוא אינו נדרס. אין fallback שמרוקן יעד כאשר מערכת הקבצים אינה תומכת בכך.

ברירת המחדל של `write_file` נשארה החלפה אטומית לקובץ יחיד. האפשרות החדשה `overwrite=False` משמשת לשמירת פלט חדש. לא שונו לוגיקת התוכן, prompts, מכסות, ספי איכות או מדיניות סיווג.

## שחזור הבדיקות

מתוך venv הפיתוח הקיים ובשורש המאגר:

```bash
python -B -m unittest discover -s tests -p test_system_io.py -v
```

זו סוויטת האימות האזרחית בלבד. אין צורך להתקין מנוע סמנטי או להריץ את בדיקות התחום הקיימות. נוסף צעד לסוויטה ב־workflow הקיים עבור Windows ו־Ubuntu; CI של השינוי הנוכחי לא הורץ במסגרת הרצה מקומית זו.

## חסמים וגבולות

- אימות מקומי בוצע ב־Windows בלבד; ריצת הסוויטה החדשה ב־Linux טרם בוצעה. אין להציג בדיקות CI קודמות כאימות התיקון הנוכחי.
- פרסום ללא דריסה דורש hard links באותה מערכת קבצים. בסביבה שאינה תומכת בהם הפעולה נכשלת בבטחה; לא נבדקו SMB/NFS או מערכות קבצים נוספות.
- הריגה קשיחה עוקפת finally ועלולה להשאיר קובץ זמני. נבדק שהיעד נשאר שלם וניתן לנסות שוב. אין מחיקה אוטומטית של קבצים לא מזוהים.
- אטומיות לקובץ יחיד אינה rollback לכמה קבצים; נבדקה התנהגות כשל חלקי, ולא נוסף מנגנון עסקאות.
- לא נבדקו הפסקת חשמל, fsync/עמידות דיסק, שירות HTTP אמיתי, מנוע ONNX/HNSW, כשירות תוכן או פרסום ייצור. הטענה להתאוששות מוגבלת להפסקת תהליך ולכשלים שהוזרקו בבדיקות.
